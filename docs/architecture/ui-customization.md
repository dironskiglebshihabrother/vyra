# Интерфейс: фронтенд и кастомизация

## Исходная идея

Экран в VYRA описан данными. Страница представляет собой документ макета в JSON, который рисует движок. Встроенные страницы собраны из таких же документов, что и пользовательские, поэтому редактору доступен весь интерфейс без исключений.

Из этого следуют три правила для кода:

- компонент страницы не знает, какие виджеты на ней стоят;
- встроенный виджет регистрируется тем же способом, что и виджет плагина;
- любой цвет, радиус, отступ и длительность анимации берётся из токена темы.

## Стек фронтенда

| Задача | Выбор | Почему | Альтернатива |
| --- | --- | --- | --- |
| Сборка | Vite, React 19, TypeScript в строгом режиме | заданы требованиями, зрелая связка с Tauri | — |
| Данные из ядра | TanStack Query | кеш запросов и точечная инвалидация по событиям из Rust | свой слой на сторах |
| Локальное состояние | Zustand | маленький, подписка на срезы без лишних перерисовок | Redux Toolkit, Jotai |
| Длинные списки | TanStack Virtual | списки и сетки на сотни тысяч строк | react-virtuoso |
| Перетаскивание | dnd-kit | работает с клавиатуры, не привязан к разметке | react-grid-layout: готовая сетка, но слабее управляется |
| Примитивы | Radix Primitives без стилей | доступность и фокус готовы, внешний вид целиком наш | React Aria, Base UI |
| Стили | CSS Modules и CSS custom properties | тема меняется сменой переменных, без пересборки и без runtime-стилей | Tailwind 4, vanilla-extract |
| Иконки | lucide | один набор, штрих 1.5, размер 16 или 18 | Phosphor |
| Схемы | zod | проверка макетов, тем и настроек виджетов при загрузке и импорте | valibot |

Tailwind не выбран по одной причине: редактор тем должен менять оформление отдельного компонента, а для этого у компонента должны быть собственные именованные переменные. С CSS Modules это прямой путь.

## Структура каталогов

```
apps/desktop/src/
  app/          запуск, провайдеры, точки входа окон (main, mini)
  ipc/          сгенерированные привязки команд, подписки на события, query client
  shell/        рамка окна, заголовок с кнопками, sidebar, панель плеера
  workspace/    движок макетов: рендер, редактор, undo/redo, схемы и их миграции
  widgets/      реестр и встроенные виджеты
  features/     library, playlists, search, queue, now-playing, metadata, files, settings, profiles
  theme/        токены, применение темы, редактор, импорт и экспорт
  ui/           примитивы: Button, Menu, Dialog, Slider, List
  plugins/      хост UI-плагинов: iframe, мост сообщений, точки расширения
  i18n/         каталоги строк
  lib/          общие хуки и утилиты
```

## Документы интерфейса

```ts
type Workspace = {
  id: string;
  name: string;
  icon: string;
  sidebar: SidebarNode[];
  pages: Record<PageKey, LayoutId>;       // home, artists, albums и пользовательские
  themeId: string | null;                 // null: тема профиля
  density: 'compact' | 'regular' | 'comfortable';
};

type LayoutDoc = {
  schema: 1;
  sections: Section[];
};

type Section = {
  id: string;
  title?: string;
  columns: 12;
  rowHeight: 8;                           // шаг сетки кратен 4 px
  items: WidgetInstance[];
};

type WidgetInstance = {
  id: string;
  type: string;                           // 'vyra.albums', 'plugin.<id>.<widget>'
  typeVersion: number;
  rect: { x: number; y: number; w: number; h: number };
  config: unknown;                        // проверяется схемой виджета
};
```

Документы хранятся в `profile.db`. У каждого есть номер схемы; при загрузке старый документ проходит цепочку миграций на TypeScript.

## Виджеты

```ts
type WidgetDefinition<C> = {
  type: string;
  version: number;
  title: MessageKey;
  icon: IconName;
  configSchema: ZodType<C>;
  defaultConfig: C;
  migrate?: (old: unknown, from: number) => C;
  size: { minW: number; minH: number; defaultW: number; defaultH: number };
  Component: FC<{ config: C; instanceId: string }>;
  Settings?: FC<{ config: C; onChange: (next: C) => void }>;
};
```

Виджеты-коллекции (альбомы, недавно добавленные, избранное, жанры, плейлисты, случайные треки) делят общий блок настроек: источник в формате Query, сортировка, фильтр, число элементов, вид (сетка, список, лента), размер плитки, набор полей. Источник исполняет Rust, тот же код обслуживает умные плейлисты.

Данные приходят страницами. Когда ядро сообщает об изменении медиатеки или статистики, фронтенд сбрасывает кеш только у запросов, которых изменение касается.

## Редактор макета

Режим редактирования включается явно. В обычном режиме код перетаскивания не загружен, он лежит в отдельном чанке.

Доступные действия: добавить, удалить, переместить, изменить размер, настроить и продублировать виджет; добавить, удалить и переставить секцию. Сетка имеет 12 колонок и шаг строки 8 px. Минимальный размер задаёт определение виджета, пересечения разрешаются сдвигом соседей вниз.

Каждое действие записывается парой патчей, прямым и обратным. На них построены Undo и Redo. Стек живёт, пока открыт редактор. Кнопка «Готово» сохраняет документ, «Отмена» возвращает состояние до входа в режим. Последние 20 сохранений макета лежат в `layout_revisions`, так что неудачную правку можно откатить и после перезапуска.

Экспорт создаёт файл `.vyralayout`: JSON с номером схемы, макетами, sidebar и списком нужных типов виджетов с версиями. При импорте документ проверяется схемой. Виджет из отсутствующего плагина заменяется заглушкой с названием плагина, остальная часть макета работает.

Узкие окна в первой версии обслуживаются контейнерными запросами внутри виджетов и схлопыванием колонок по порогам. Отдельные раскладки под разную ширину можно добавить позже, формат документа это допускает.

## Sidebar

```ts
type SidebarNode = { id: string; hidden?: boolean; pinned?: boolean } & (
  | { kind: 'group'; label: string; collapsed: boolean; children: SidebarNode[] }
  | { kind: 'page'; page: PageKey; label?: string; icon?: IconName }
  | { kind: 'playlist'; playlistId: string; label?: string; icon?: IconName }
  | { kind: 'query'; label: string; icon: IconName; query: Query }   // пользовательский раздел
  | { kind: 'plugin'; pluginId: string; viewId: string; label?: string; icon?: IconName }
  | { kind: 'separator' }
);
```

Узел `query` создаёт пользовательский раздел: например, «Джаз в 24 бит» с собственной иконкой. Редактор работает на месте: перетаскивание, переименование двойным щелчком, выбор иконки из набора.

## Рабочие пространства

Рабочее пространство объединяет sidebar, набор страниц, плотность и, по желанию, собственную тему. Шаблоны Main, Artists, Audiophile, Minimal и Discover поставляются как обычные документы, их можно изменить или удалить.

Переключение меняет только дерево React. Воспроизведение идёт в Rust и о смене пространства не узнаёт.

## Темы

Тема состоит из трёх слоёв токенов.

| Слой | Примеры | Кто обычно меняет |
| --- | --- | --- |
| Базовый | нейтральная шкала, акцент, шкала отступов, радиусы, шрифты, длительности | пользователь в простом редакторе |
| Смысловой | фон страницы, карточка, поднятая поверхность, три роли текста, линия | автор темы |
| Компонентный | фон панели плеера, высота строки sidebar, радиус обложки | автор темы, точечно |

```json
{
  "schema": 1,
  "name": "Graphite",
  "extends": "vyra.dark",
  "tokens": {
    "color.surface.page": "#141415",
    "color.surface.card": "#19191b",
    "color.text.primary": "#ededed",
    "color.accent": "#b3a6dc",
    "radius.card": 12,
    "motion.ease": "cubic-bezier(0.22, 1, 0.36, 1)"
  },
  "materials": {
    "menu":      { "type": "glass", "blur": 24, "opacity": 0.72 },
    "playerBar": { "type": "solid" }
  },
  "components": { "sidebar.item.height": 32 },
  "css": null
}
```

Значения токенов превращаются в CSS custom properties на корневом элементе. Смена темы не перестраивает дерево компонентов.

Материал поверхности выбирается из четырёх типов: сплошной, полупрозрачный, стекло (размытие содержимого под поверхностью) и системный Mica, доступный в Windows 11. Набор готовых тем ничем не ограничивает пользователя: любая тема, включая встроенные, есть документ с токенами, который можно скопировать и переписать.

Палитру обложки считает Rust при кешировании изображения, 4–6 цветов сохраняются в базе. Фронтенд выставляет их как `--artwork-*`. Тема сама решает, использовать ли их: для акцента, для фона экрана «Сейчас играет» или нигде.

Пользовательские шрифты лежат в папке профиля и подключаются через `FontFace`.

Поле `css` принимает произвольные стили. Ими можно сломать интерфейс, поэтому есть безопасный запуск: ключ `--safe-mode` или удержание Shift при старте загружают базовую тему и стандартный макет.

Редактор тем предупреждает, если контраст текста на акценте ниже 4.5:1. Запрета нет, решение остаётся за пользователем.

## Тёмная тема в приоритете

Интерфейс проектируется сначала в тёмной теме. Все макеты, состояния и иллюстрации проверяются в ней, светлая тема выводится из тех же токенов вторым шагом. В MVP входит одна доведённая тёмная тема и редактирование акцента; светлая появляется вместе с редактором тем.

Тёмная тема по умолчанию следует правилам unslop:

- поверхности берутся из одной нейтральной шкалы graphite: `#0f0f10` для sidebar, `#141415` для страницы, `#19191b` для карточек, `#232325` для поднятых элементов;
- глубину создают ступени поверхности и тонкая линия (основной цвет текста при 8% непрозрачности), теней в тёмной теме нет;
- акцент один и занимает несколько процентов экрана: основное действие, выделение, текущий трек;
- три роли текста, два веса шрифта (400 и 500), подписи в обычном регистре;
- отступы кратны 4 px, строка навигации 32–36 px, sidebar 240–280 px;
- вложенный радиус равен внешнему минус отступ.

Цвет приходит из содержимого. В музыкальном плеере это обложки: сетка альбомов и экран «Сейчас играет» несут весь цвет, рамка вокруг них остаётся серой.

## Черновик направления

Руководство unslop требует до начала визуальной работы записать пять строк и согласовать их. Ниже черновик для обсуждения, решение Р16.

- **Продукт.** Локальный музыкальный центр для Windows для тех, кто держит коллекцию на своём диске и хочет устроить плеер по-своему.
- **Характер.** Спокойный, точный, с глубиной.
- **Мир.** Тонированное стекло, сложенное слоями: пластины накладываются друг на друга, и цвет на пересечении меняется. Так же устроен интерфейс VYRA: панели и виджеты лежат слоями, раскладывает их пользователь.
- **Моменты.** Обложка на экране «Сейчас играет» и сетка обложек в медиатеке.
- **Подпись.** Строка пути сигнала в панели плеера: формат файла, обработка, устройство. Когда путь не меняет звук, в ней стоит отметка bit-perfect.

Строка пути сигнала выбрана потому, что её не может быть у плеера без такого аудиодвижка.

Строки «Характер» и «Мир» пересмотрены 20 ноября 2026 года. Первый вариант опирался на образы старой аппаратуры, от них отказались при выборе знака. Новый мир взят из выбранного знака «Слои». В теме по умолчанию слои передаются ступенями поверхности, размытие для этого не нужно.

## Расхождение требований с unslop

В требованиях названы Liquid Glass, размытие, прозрачность и динамический фон из цветов обложки. Unslop относит стекло, цветные заливки за содержимым и крупные размытия к признакам шаблонного интерфейса и запрещает заменять один модный приём другим.

Предлагаемое разрешение. Тема по умолчанию строится по unslop. Стекло и фон из обложки остаются возможностями движка тем и входят в отдельную встроенную тему, которую пользователь включает сам. Движок их поддерживает полностью, но внешний вид VYRA «из коробки» на них не опирается. Выбор записан в решении Р15.

Название Liquid Glass принадлежит Apple, как и шрифт SF Pro с набором SF Symbols, лицензии которых не разрешают использование в приложениях для Windows. Встроенная тема получит своё имя, шрифты и иконки берутся из свободных.

## Тексты интерфейса

Все строки лежат в каталогах `i18n`, в компонентах текста нет. Каждая новая строка проходит вычитку по списку:

1. Подпись называет действие или объект одним-двумя словами: «Поиск», «В очередь».
2. Восклицательных знаков нет. Короткая строка заканчивается без точки.
3. Приветствий и подводок нет. Заголовок называет место: «Альбомы», «Ноябрь 2026».
4. Конструкции «не А, а Б» и тройки однородных слов не используются.
5. Канцелярит заменяется прямой речью: «Удалить 12 файлов?» вместо «Вы уверены, что хотите выполнить удаление выбранных файлов?»
6. Сообщение об ошибке называет файл, устройство и причину: «Устройство FiiO K7 занято другой программой».
7. Одна мысль высказывается один раз.
8. Тире, скобки и кавычки ставятся только там, где без них нельзя.
9. Числа записаны в одном формате и набраны цифрами одинаковой ширины.
10. Регистр обычный: «Недавно добавленные».

Список соединяет собственные правила проекта и раздел Copy из unslop.

## Бюджет производительности

Цель: 60 кадров в секунду во всех взаимодействиях на эталонной машине. Эталон выбран в решении Р17: ПК с дискретной видеокартой уровня GTX 1650 и 16 ГБ памяти.

На встроенной графике 60 кадров не гарантируются. Для таких машин есть настройка «Упростить эффекты»: она отключает размытие и длинные анимации.

Правила, которые удерживают бюджет:

- анимируются только `transform` и `opacity`; ширина, высота, отступы и большие размытия не анимируются;
- одна кривая `cubic-bezier(0.22, 1, 0.36, 1)`, длительности 120–180 мс для отклика и 300–500 мс для появления;
- списки и сетки виртуализированы, обложки запрашиваются в размере плитки;
- размытие фона применяется к небольшим поверхностям (меню, панель плеера) и не лежит под прокручиваемым списком;
- позиция воспроизведения интерполируется на фронтенде, ядро присылает опорные точки несколько раз в секунду;
- ни одна команда IPC не возвращает больше одной страницы данных.

В отладочной сборке работает счётчик времени кадра. Сценарии прокрутки и переходов измеряются автоматически, кадр длиннее 16,7 мс в них считается дефектом.

## Окна

Главное окно и мини-плеер имеют отдельные точки входа и общий набор токенов. Мини-плеер собран в лёгкий бандл без редактора, виджетов и настроек. Оба окна без системной рамки, кнопки управления свои; подробности в [windows-integration.md](windows-integration.md).
