# Плагины

## Три вида в одном пакете

Плагин поставляется файлом `.vyraplugin`. Это zip-архив с манифестом и до трёх частей:

| Часть | Где исполняется | Чем изолирована |
| --- | --- | --- |
| UI | WebView2, отдельный iframe | песочница iframe, собственный origin, мост сообщений |
| Core | процесс Rust, Wasmtime | WASM-компонент, доступ только к выданным функциям хоста |
| DSP | поток обработки аудиодвижка, Wasmtime | WASM без импортов, только вычисления |

Простому плагину хватает одной части. Скробблер состоит из core-части и экрана настроек, визуализатор из одной UI-части.

## Манифест

```toml
id      = "org.example.lastfm"
name    = "Last.fm"
version = "1.2.0"
api     = "1"                 # мажорная версия API хоста
min_app = "1.0.0"

[core]
component = "core.wasm"

[ui]
entry = "ui/index.html"

[[ui.widgets]]
id    = "recent-scrobbles"
title = "Недавние скробблы"

[permissions]
library  = "read"
playback = "observe"
network  = ["ws.audioscrobbler.com"]
storage  = true
```

## Разрешения

| Разрешение | Что открывает |
| --- | --- |
| `library = "read"` | запросы к медиатеке на языке Query |
| `library = "suggest"` | предложения правок метаданных; применяет их пользователь |
| `playback = "observe"` | события о треках и состоянии |
| `playback = "control"` | команды воспроизведения и очереди |
| `stats = "read"` | история и статистика активного профиля |
| `network = [...]` | HTTP-запросы к перечисленным хостам |
| `local-ipc = [...]` | именованные каналы из списка, нужно для Discord RPC |
| `files = "sidecar"` | чтение файлов рядом с треком, например `.lrc` |
| `storage` | своя папка и хранилище ключ-значение в профиле |
| `audio = "tap"` | поток семплов или спектра для визуализации |
| `audio = "dsp"` | узел в цепочке обработки |
| `notifications` | системные уведомления |

Разрешения показываются при установке. Обновление, которое просит новые разрешения, требует повторного согласия. Выданные разрешения хранятся в профиле: один пользователь может разрешить плагину сеть, другой нет.

Прямой записи в теги у плагинов нет. Режим метаданных ручной, поэтому плагин формирует предложение, а пользователь принимает его в редакторе.

## UI-плагины

Каждое представление плагина живёт в iframe с атрибутом `sandbox="allow-scripts"`. Содержимое отдаётся по собственной схеме `vyra-plugin://<id>/`, у каждого плагина свой origin. Строгая политика CSP запрещает загрузку кода из сети.

К IPC Tauri плагин доступа не имеет. Он шлёт сообщения через `postMessage` мосту на стороне хоста. Мост сверяет вызов с разрешениями и только потом обращается к ядру. Проверка того, что iframe с чужим origin действительно не видит API Tauri, входит в прототип П10.

Точки расширения:

- виджеты для макетов;
- разделы в sidebar;
- панель на экране «Сейчас играет», например текст песни;
- пункты контекстного меню, описанные в манифесте;
- страница настроек плагина.

Хост передаёт в iframe токены активной темы в виде CSS-переменных. Плагин, который ими пользуется, выглядит родным в любой теме.

Ограничение подхода: iframe тяжелее обычного компонента, у каждого свой контекст JavaScript. Поэтому один плагин получает один iframe на представление, невидимые представления приостанавливаются. Менять оформление самой VYRA плагин не может, для этого существуют темы.

## Core-плагины

Среда исполнения: Wasmtime и компонентная модель. Интерфейсы описаны на WIT и версионируются как пакеты.

```wit
package vyra:plugin@1.0.0;

interface playback-events {
  record track {
    uid: string,
    title: string,
    artist: string,
    album: string,
    duration-ms: u32,
  }
  on-track-started: func(t: track, at: u64);
  on-track-finished: func(t: track, played-ms: u32, completed: bool);
}

world core-plugin {
  import vyra:host/library@1.0.0;
  import vyra:host/storage@1.0.0;
  import vyra:host/http@1.0.0;
  export playback-events;
  export lifecycle;
}
```

Функции хоста, на которые у плагина нет разрешения, в его экземпляр не подключаются вовсе.

Ограничения на экземпляр: 64 МБ памяти, 100 мс на обработчик события, прерывание по эпохам для зависшего кода. Сбой выгружает экземпляр. После трёх сбоев подряд плагин отключается, пользователь видит причину.

Core-плагины не зависят от окна. Скробблер продолжает работать, когда интерфейс закрыт в трей.

### Почему Wasmtime

Wasmtime развивает Bytecode Alliance, это эталонная реализация компонентной модели. WASI 0.3 с асинхронными вызовами стабилизирован в июне 2026 года и включён по умолчанию с версии 46. Асинхронность нужна сетевым плагинам, поэтому API стоит сразу строить на 0.3.

Цена: размер. Сборка с компилятором Cranelift добавляет к программе порядка 15–20 МБ. Точную цифру для Windows даст прототип П10.

Рассмотренные альтернативы:

- **Extism.** Обёртка над Wasmtime с простым API. Удобна для старта, но скрывает компонентную модель и WIT, на которых строится версионирование.
- **Встроенный интерпретатор JavaScript или Lua.** Авторам проще писать, однако изоляция и контроль ресурсов слабее, а для DSP такой вариант не годится.
- **Нативные DLL.** Полная скорость и никакой изоляции. Сбой плагина роняет плеер.

Слабое место WASM: порог входа для авторов. Писать компоненты удобно на Rust, C и Go. JavaScript собирается в компонент вместе с движком и весит около 10 МБ на плагин. Насколько это мешает, зависит от того, кого мы видим авторами плагинов; вопрос записан в решении Р12.

## DSP-плагины

Узел плагина исполняется в потоке обработки, а не в потоке вывода. Между ними стоит кольцевой буфер, поэтому жёсткого реального времени от плагина не требуется. Требование мягче: блок должен обрабатываться быстрее, чем он звучит.

Правила:

- мир DSP не импортирует ничего: ни файлов, ни сети, ни часов;
- экспортируются `prepare`, `process`, `latency`, `set-param`, `reset`;
- память выделяется в `prepare`, рост памяти во время `process` запрещён ограничителем;
- хост копирует блок в память плагина и обратно; при 1024 кадрах стерео это 16 КБ, затраты пренебрежимы;
- время каждого вызова измеряется. Узел, который стабильно не укладывается, обходится, плагин помечается как медленный.

Любой активный DSP-плагин снимает признак bit-perfect. Строка пути сигнала показывает его как отдельную стадию.

Код WASM после компиляции Cranelift работает в 1,2–2 раза медленнее нативного. Для эквалайзеров, кроссфида и подобных задач запаса достаточно. Свёртка с длинными импульсами может упереться в этот предел; прототип П10 измеряет его.

Хостинг нативных плагинов CLAP и VST3 отнесён к долгосрочным возможностям. Лицензионно путь открыт: VST3 SDK с октября 2025 года распространяется под MIT. Препятствие техническое: нативный плагин не изолирован, для него понадобится отдельный процесс.

## Версии и совместимость

У API хоста есть мажорная и минорная версия. Минорная добавляет функции, мажорная может ломать. Хост поддерживает текущую мажорную версию и предыдущую.

Совместимость проверяется при установке и при каждой загрузке: поле `api`, поле `min_app`, версии пакетов WIT внутри компонента. Несовместимый плагин остаётся установленным, но выключенным, с понятной причиной в списке.

SDK для TypeScript и Rust генерируются из тех же описаний, что и хост, и получают те же номера версий.

## Жизненный цикл

Установка идёт из файла: проверка манифеста и контрольных сумм, экран с разрешениями, распаковка в `plugins\<id>\<version>`. Пакет общий для всех профилей. Включение, настройки и разрешения у каждого профиля свои.

Удаление стирает пакет. Данные плагина в профилях удаляются по выбору пользователя.

Безопасный запуск отключает все плагины вместе с пользовательской темой.

Каталог плагинов и проверка издателей не входят в первую версию системы. Сначала плагины ставятся только из локальных файлов.

## Что закладывается до появления плагинов

Хост плагинов появится после версии 1.0. До этого встроенные функции строятся на тех же точках расширения, которые потом получат плагины:

- реестр виджетов;
- описательные точки расширения для sidebar и меню;
- шина событий ядра с типизированными темами;
- трейт `DspNode`;
- язык запросов Query.

Когда встроенный эквалайзер живёт на `DspNode`, а встроенные виджеты регистрируются через реестр, публичный API получается из работающего кода, и ядро переписывать не приходится.

## Примеры из требований

| Плагин | Части | Разрешения |
| --- | --- | --- |
| Тексты песен | UI, core | `files = "sidecar"`, `playback = "observe"` |
| Last.fm | core, UI для настроек | `playback = "observe"`, `network` |
| Discord RPC | core | `playback = "observe"`, `local-ipc` |
| Визуализатор | UI | `audio = "tap"` |
| Инструменты метаданных | core, UI | `library = "read"`, `library = "suggest"` |
| Статистика | UI | `stats = "read"`, `library = "read"` |
| Кроссфид | DSP | `audio = "dsp"` |
