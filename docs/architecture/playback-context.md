# Playback Context Engine

Модуль отвечает на вопрос, что играет после текущего трека и почему. Он живёт в крейте `vyra-playback`, ничего не знает о React и получает от интерфейса только намерение пользователя.

## Термины

**Источник запуска** (origin) сообщает, откуда пришла команда: страница альбома, плейлист, список треков, проводник Windows, перетаскивание в окно, командная строка, виджет, плагин.

**Контекст** описывает набор треков и их порядок. В базе и в памяти он хранится как дескриптор, а список треков из него строит резолвер.

**Очередь** содержит то, что реально пойдёт на воспроизведение: треки контекста плюс добавленное пользователем вручную.

## Модель

```rust
enum ContextKind {
    Album { album_uid: Uid, disc: Option<u16> },
    Playlist { playlist_id: Uid },
    SmartPlaylist { playlist_id: Uid },        // при запуске фиксируется снимок результата
    Folder { path: PathBuf, depth: FolderDepth },
    Artist { artist_id: Uid, scope: ArtistScope },
    Genre { genre_id: Uid },
    LibraryView { query: Query },              // список с фильтром и сортировкой, тоже снимок
    AdHocFiles { paths: Vec<PathBuf> },        // несколько файлов, открытых одной операцией
    Single { track: TrackRef },
}

struct PlayRequest {
    origin: Origin,
    target: TrackRef,              // uid трека медиатеки или путь к файлу вне её
    hint: Option<ContextKind>,     // контекст экрана, с которого запустили
    mode: PlayMode,                // Auto | OnlyThisTrack | FromHere | WholeContext
}

struct ResolvedContext {
    kind: ContextKind,
    items: Vec<TrackRef>,          // порядок без shuffle
    start_index: usize,
    at_end: EndBehavior,           // Stop | Repeat | NextAlbum
    gain_mode: GainMode,           // Album | Track, для ReplayGain
    confidence: Confidence,
    reason: ResolveReason,         // почему выбран этот контекст
}
```

`reason` показывается в интерфейсе рядом с очередью и пишется в лог. Строка называет контекст и размер очереди: «Альбом Kind of Blue, 5 треков», «Папка Jazz, 14 файлов», «Одиночный трек». Когда поведение кажется пользователю странным, по этой строке видно, какое правило сработало.

## Правила по умолчанию

| Действие | Контекст | В конце |
| --- | --- | --- |
| Трек на странице альбома | Album, с выбранного трека | стоп |
| Кнопка воспроизведения у альбома | Album, с первого трека | стоп |
| Плейлист или трек в нём | Playlist | стоп |
| Файл из проводника, которого нет в медиатеке | Single | стоп |
| Файл из проводника, который есть в медиатеке | Single, решение Р3 | стоп |
| Несколько файлов, открытых вместе | AdHocFiles, порядок по имени | стоп |
| Папка | Folder | стоп |
| Трек в общем списке треков | LibraryView, решение Р4 | стоп |
| Трек на странице артиста | Artist | стоп |
| Трек в результатах поиска | Single, решение Р4 | стоп |
| Команда «Только этот трек» | Single | стоп |

Номера Р3 и Р4 ссылаются на [decisions.md](decisions.md): эти строки зависят от продуктового выбора. Повтор включается отдельным переключателем и заменяет «стоп» на возврат к началу контекста.

Каждая строка таблицы хранится как настройка профиля. Меню трека всегда содержит четыре явные команды: «Только этот трек», «Играть отсюда», «Играть альбом», «Играть папку».

### Продолжение после альбома

Настройка «Продолжать после альбома» по умолчанию выключена. Когда она включена, после последнего трека начинается следующий альбом того же исполнителя по году выпуска. После последнего альбома воспроизведение останавливается.

### Режим альбомного контекста

Настройка профиля с тремя значениями.

| Режим | Что происходит при щелчке по треку |
| --- | --- |
| Гибрид, по умолчанию | играет альбом из медиатеки, если уверенность не ниже порога; иначе один трек |
| По метаданным | играет альбом из медиатеки при любой уверенности, кроме none |
| По папке | играет папка трека по порядку имён файлов, теги на состав очереди не влияют |

Режим меняет только выбор контекста при воспроизведении. Состав альбомов в медиатеке от него не зависит, его определяет Album Resolver.

### Возврат к контексту

Для каждого альбома, плейлиста и папки профиль запоминает последний игравший трек и позицию в нём. Страница альбома, с которого пользователь ушёл на середине, показывает кнопку «Продолжить с трека 5». Обычная кнопка воспроизведения по-прежнему начинает с первого трека.

Точка возврата хранится в таблице `resume_points` и стирается, когда контекст доигран до конца.

## Как строится контекст

1. Цель нормализуется. Путь к файлу превращается в запись медиатеки, если файл известен. Для неизвестного файла теги читаются на лету, запись в базу не попадает.
2. Режим `OnlyThisTrack` сразу даёт `Single`.
3. Если интерфейс передал `hint`, резолвер проверяет, что трек входит в этот набор, и строит список.
4. Если подсказки нет (внешнее открытие), применяется правило для этого источника из настроек профиля.
5. Для альбомного контекста проверяется уверенность в альбоме. Ниже порога контекст понижается до `Single`.
6. Рассчитываются порядок, режим ReplayGain и поведение в конце.

## Очередь

Очередь состоит из трёх слоёв. Первый слой содержит треки контекста в исходном порядке и текущую перестановку shuffle. Второй хранит добавленное командами «Играть следующим» и «В очередь»; эти треки звучат раньше, чем воспроизведение вернётся в контекст. Третий слой ведёт историю для кнопки «Назад».

Shuffle хранит seed и перестановку. При выключении порядок возвращается к исходному, начиная с текущего трека.

При запуске из `LibraryView` и `SmartPlaylist` фиксируется список uid на момент запуска. Сканирование или правка тегов не перетасовывают играющую очередь. Пропавший файл пропускается, в лог пишется причина, в очереди трек помечается как недоступный.

Очередь принадлежит Rust-ядру. Интерфейс получает снимок и последующие изменения событиями, поэтому главное окно и мини-плеер показывают одно и то же.

## Открытие извне

Приложение работает в одном экземпляре. Второй запуск передаёт свои аргументы работающему процессу и завершается.

Проводник при открытии нескольких выделенных файлов запускает программу по разу на каждый файл. Запросы, пришедшие в окне 250 мс, объединяются в один `AdHocFiles`. Длину окна нужно подобрать на прототипе: на медленном диске процессы стартуют с большим разбросом.

Папку можно открыть из контекстного меню проводника и перетаскиванием. Порядок внутри папки задаёт естественная сортировка имён (`2.mp3` раньше `10.mp3`), теги на порядок не влияют. Подпапки обрабатываются так:

- если в папке есть аудиофайлы, играют они, а подпапки вида `CD1`, `Disc 2`, `Диск 3` подключаются как диски;
- если аудиофайлов на верхнем уровне нет, подпапки обходятся по порядку имён.

Это поведение по умолчанию, окончательный выбор вынесен в решение Р5.

## Определение альбома

Album Resolver работает в сканере медиатеки. Результат лежит в базе, а движок воспроизведения читает готовую оценку уверенности.

Запись в таблице `albums` означает конкретное издание. Ремастер 2011 года и оригинальный релиз занимают две строки. Связь изданий одной записи хранится в `album_group_id` и заполняется позже, из MusicBrainz Release Group ID или вручную.

### Признаки группировки

Признаки перечислены от сильного к слабому.

1. Ручное решение пользователя: объединить или разделить. Оно хранится в `album_overrides`, переживает пересканирование и в теги не пишется.
2. MusicBrainz Release ID в тегах. Одинаковый идентификатор означает одно издание. Разные идентификаторы означают разные издания даже при одинаковом названии.
3. Кластер папки: файлы одной папки или соседних папок дисков с общим родителем, у которых совпадают нормализованное название альбома и album artist либо стоит признак компиляции.
4. Между папками без общего родителя треки автоматически не объединяются. Совпадение названия и артиста даёт только запись «возможно, один альбом» в списке проблем медиатеки. Смягчение этого правила предложено в решении Р21.

Нормализация названия приводит Unicode к NFKC, выравнивает регистр, пробелы, кавычки и тире. Пометки вроде `(Deluxe Edition)` и `[Remastered 2011]` остаются частью названия, потому что отличают одно издание от другого.

### Уверенность

| Уровень | Когда присваивается |
| --- | --- |
| confirmed | ручное решение или MusicBrainz Release ID |
| high | кластер папки, album artist задан и согласован, номера треков без конфликтов |
| medium | кластер папки, album artist выведен из тегов исполнителя, либо в номерах есть пропуски |
| low | конфликт номеров, разные годы внутри кластера, часть файлов папки без тега альбома |
| none | тега альбома нет |

Автоматический альбомный контекст включается от уровня medium. Порог настраивается. При уровне low страница альбома показывает предупреждение и список найденных расхождений.

### Частные случаи

| Случай | Поведение |
| --- | --- |
| Несколько дисков | Порядок по паре (диск, трек). Номер диска берётся из тега, затем из имени папки (`CD2`), затем из префикса имени файла (`2-05`). Воспроизведение переходит через границу дисков без остановки |
| Компиляция | Признак `TCMP`, `cpil`, `COMPILATION` или album artist «Various Artists». Группировка по альбому и папке, исполнитель трека не учитывается |
| Нет album artist | Берётся исполнитель, если он один на весь кластер. При разных исполнителях кластер считается компиляцией с уровнем medium |
| Разные издания | Отдельные записи. В интерфейсе стоят рядом с меткой издания: год, формат, разрядность |
| Повтор пары (диск, трек) | Альбом получает флаг `ordering_conflict` и уровень low. Порядок: диск, трек, имя файла. В `library_issues` появляется предложение исправить номера |
| Один альбом в FLAC и MP3 в разных папках | Два издания. Пара попадает в отчёт о дубликатах |
| Два альбома в одной папке | Два кластера по названию, уверенность считается для каждого |
| Трек без тега альбома | `album_id` пуст. Общий «Unknown Album» на всю медиатеку не создаётся |
| Дерево `Artist/Album/CD1` | Папкой альбома считается родитель папок дисков |

### Стабильность идентификаторов

Uid альбома закрепляется при создании. Когда пользователь правит название или год, альбом сохраняет uid, если больше половины треков остались теми же. Иначе избранные альбомы в профилях потеряли бы связь после обычной правки тегов.

## Связь с аудиодвижком

Gapless работает всегда, когда соседние треки имеют одинаковый формат потока. От контекста зависят две вещи. ReplayGain использует album gain в альбомном контексте с уверенностью от high и track gain в остальных случаях. Crossfade, когда он появится, в альбомном контексте будет выключен.

В `play_events` записывается вид контекста. По этому полю статистика отличает прослушивание альбома целиком от случайного трека.

## Тесты

Резолвер проверяется таблицами: на входе дерево файлов с тегами, на выходе ожидаемые альбомы, порядок и уверенность. Фикстуры лежат в `tests/fixtures/libraries` и состоят из односекундных файлов с намеренно испорченными тегами. Генератор фикстур описывает каждое дерево в TOML, поэтому новый случай из реальной коллекции добавляется за несколько минут.

Отдельный тест проверяет, что повторное сканирование той же папки не меняет uid альбомов и треков.
