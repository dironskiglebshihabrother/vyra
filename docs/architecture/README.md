## 1. Общая схема

```
┌───────────────────────────── vyra.exe ─────────────────────────────┐
│  Оболочка Tauri: команды IPC, окна, трей, протоколы                │
│ ────────────────────────────────────────────────────────────────── │
│  vyra-core: сервисы, шина событий, фоновые задачи                  │
│    playback   контекст, очередь, сессия                            │
│    library    сканер, наблюдение за папками, альбомы, поиск        │
│    metadata   чтение и запись тегов                                │
│    files      операции с файлами и их журнал                       │
│    profiles   профили и настройки                                  │
│    plugins    хост WASM                                            │
│    db         SQLite                                               │
│ ────────────────────────────────────────────────────────────────── │
│  vyra-audio: собственные потоки                                    │
│    декодер → обработка → вывод WASAPI                              │
└────────────────────────────────────────────────────────────────────┘
          ▲  команды, события, каналы, vyra-art://
          ▼
┌──────────────────────── процессы WebView2 ─────────────────────────┐
│  React: главное окно, мини-плеер                                   │
│  UI-плагины в изолированных iframe                                 │
└────────────────────────────────────────────────────────────────────┘
```

Три свойства, на которых держится остальное.

Звук живёт в процессе Rust и в своих потоках. WebView2 работает в отдельных процессах. Зависший или перезапущенный интерфейс музыку не останавливает, окно можно закрыть в трей целиком.

Ядро не зависит от Tauri. Крейт `vyra-core` собирается в консольную утилиту `vyra-cli`, через которую гоняются тесты, бенчмарки сканера и диагностика звука без окна.

Интерфейс является клиентом. Состояние воспроизведения, очередь и медиатека принадлежат ядру. Фронтенд хранит только то, что относится к отображению.

## 2. Стек

| Область | Выбор | Почему | Ограничения | Что ещё рассматривалось |
| --- | --- | --- | --- | --- |
| Оболочка | Tauri 2 (сейчас 2.12) | ядро на Rust в одном процессе с оболочкой, малый размер, интерфейс на веб-технологиях даёт глубокую кастомизацию и UI-плагины | нужен WebView2; обмен с интерфейсом идёт через сериализацию; общей памяти с окном нет | Electron: зрелее, но тяжелее, а Rust пришлось бы подключать модулем Node. Qt, WinUI, Slint: быстрее рисуют, но редактор макетов, темы и плагины интерфейса обошлись бы в разы дороже |
| Ядро | Rust | звук в реальном времени без сборщика мусора; безопасный разбор чужих файлов | долгая сборка; готовых аудиобиблиотек меньше, чем в C++ | C++ с JUCE |
| Интерфейс | React 19, TypeScript | задан требованиями; крупнейшая экосистема для редакторов с перетаскиванием | длинные списки требуют виртуализации | Solid, Svelte: быстрее, экосистема уже |
| База | SQLite через `rusqlite` | один файл, FTS5, online backup, `ATTACH` для профилей | один пишущий поток на базу | `sqlx`; встроенные key-value хранилища не дают запросов для умных плейлистов |
| Вывод звука | WASAPI через крейт `wasapi` | общий и монопольный режимы, работа по событию, уведомления об устройствах | только Windows | CPAL: нет монопольного режима, подробности в [audio-engine.md](audio-engine.md) |
| Декодирование | Symphonia 0.6 | чистый Rust, gapless для основных форматов | нет Opus, HE-AAC, WavPack, APE, WMA, AC3, DTS, DSD | FFmpeg как единственный декодер: покрывает всё, но тянет DLL и лицензионные условия в базовую поставку |
| Редкие форматы | FFmpeg, сборка LGPL, отдельная DLL | закрывает WMA, APE, WavPack, AC3, DTS, HE-AAC | размер, условия LGPL | Media Foundation для WMA и AAC; отдельные библиотеки на формат |
| Теги | `lofty` 0.25 для основных форматов, TagLib 2.3 для WMA, DSF, DFF, TTA и MKA | `lofty` написан на Rust и безопасен на повреждённых файлах; TagLib закрывает форматы, которых в `lofty` нет | TagLib приносит C++ и CMake в сборку | один TagLib на всё: проще, но разбор на C++ в сканере может уронить процесс |
| Ресемплинг | `rubato` 5 | качественная синк-интерполяция на чистом Rust | три мажорные версии за 2026 год | `libsoxr` через FFI |
| Наблюдение за папками | `notify` с накоплением событий | надстройка над `ReadDirectoryChangesW` | на сетевых папках события ненадёжны, нужна периодическая сверка | опрос по таймеру как единственный способ |
| Плагины | Wasmtime, компонентная модель | изоляция, контроль ресурсов, версии интерфейсов на WIT | около 15–20 МБ к размеру; порог входа для авторов | Extism, встроенный JavaScript, нативные DLL |
| Типы для IPC | `tauri-specta` 2.0 | команды и события Rust превращаются в типизированные функции TypeScript | версия 2 до сих пор в статусе RC; фиксировать точный номер | `ts-rs` и обёртки вручную |
| Системные элементы управления | `souvlaki` или `windows` | карточка трека в системе, мультимедийные клавиши | привязка к окну | — |

Отступление от исходного списка одно: CPAL заменён прямой работой с WASAPI. Остальные технологии из брифа остаются.

Tauri 3 существует в альфа-версиях. Проект начинается на 2.x; переход оценивается после стабильного выпуска.

## 3. Rust-ядро

### Крейты

| Крейт | Отвечает за | От кого зависит |
| --- | --- | --- |
| `vyra-types` | идентификаторы, общие структуры, коды ошибок | — |
| `vyra-audio` | конвейер звука, декодеры, вывод, устройства | `vyra-types` |
| `vyra-db` | соединения, миграции, запросы, язык Query | `vyra-types` |
| `vyra-metadata` | движки тегов, модель полей, форматные строки, действия, сессия правки | `vyra-types` |
| `vyra-library` | сканер, наблюдение, определение альбомов, кеш обложек, поиск | `vyra-db`, `vyra-metadata` |
| `vyra-playback` | контекст, очередь, сессия, статистика | `vyra-db`, `vyra-audio` |
| `vyra-files` | файловые операции, журнал, дубликаты | `vyra-db`, `vyra-metadata` |
| `vyra-profiles` | профили, настройки, резервные копии | `vyra-db` |
| `vyra-platform` | SMTC, типы файлов, панель задач, питание | `vyra-types` |
| `vyra-plugins` | хост WASM, манифесты, разрешения | `vyra-core` через трейты |
| `vyra-core` | сборка сервисов, шина событий, фоновые задачи; единственная точка входа для оболочки | все перечисленные |
| `vyra-cli` | консольная утилита | `vyra-core` |

Два запрета проверяются в CI: `vyra-audio` не подключает `vyra-db`, и ни один крейт, кроме оболочки, не подключает `tauri`.

В MVP крейты `vyra-files` и `vyra-plugins` пусты или отсутствуют. Границы остальных проведены сразу, потому что перенос кода между крейтами позже обходится дороже.

### Потоки

- Асинхронные задачи ядра и обработчики IPC работают на рантайме `tokio`, который уже есть в Tauri.
- Сканирование и расчёт отпечатков идут в ограниченном пуле потоков с фоновым приоритетом.
- У каждой базы один пишущий поток с очередью команд.
- Звук занимает четыре собственных потока, описанных в [audio-engine.md](audio-engine.md).

### Сканер медиатеки

Обход каталогов сравнивает тройку путь, размер и время изменения с базой и берёт в работу только изменившиеся файлы. Теги читаются параллельно, записи идут в базу пачками по 500 файлов в одной транзакции. События о ходе сканирования уходят в интерфейс не чаще пяти раз в секунду.

Наблюдение за папками накапливает события две секунды и передаёт сканеру список затронутых каталогов. Наблюдатель может пропустить изменения, пока программа закрыта или папка лежит в сети. Поэтому при запуске выполняется быстрая сверка, а сетевые корни пересматриваются по расписанию.

Пути хранятся как пара корень и относительный путь. Перенос всей коллекции на другой диск сводится к изменению одной строки. Длинные пути открываются с префиксом `\\?\`.

Корни добавляются вручную, можно несколько за раз. Есть режим «Стандартные папки», который подключает «Музыку» и «Загрузки» пользователя Windows. По умолчанию он выключен: в «Загрузках» лежат голосовые сообщения и случайные звуки, в медиатеке они мешают.

Сканирование запускается при старте, по расписанию и вручную.

Правила пропуска лежат в таблице `scan_rules`: папки-исключения, расширения, скрытые файлы и папки.

Неизменённый файл определяется по размеру и времени изменения. Хеш содержимого для этого не считается: читать каждый файл ради проверки означало бы превратить инкрементальное сканирование в полное. Отпечаток `audio_fp` считается один раз при импорте и пересчитывается только у изменившихся файлов.

Повреждённый файл не останавливает сканирование. Он получает статус `unreadable`, причина пишется в журнал и в список проблем медиатеки.

Лист CUE рядом с образом превращается в отдельные треки с границами внутри общего файла. Подробности в [audio-engine.md](audio-engine.md).

### Метаданные

Режим ручной. Сканер только читает. Запись в файл происходит по команде пользователя из редактора, одиночного или массового.

Проверки находят типовые ошибки: пропущенный album artist, повтор номеров, разный год внутри альбома, лишние пробелы, несовпадение регистра у одного исполнителя. Каждая находка попадает в `library_issues` с готовым предложением. Применяет его пользователь.

Перед записью прежние значения сохраняются в журнал `file_ops`, включая заменяемую обложку. Правку можно отменить. Способ записи (через временную копию или на месте) вынесен в решение Р9.

Редактор работает с полями Title, Artist, Album, Album Artist, Track Number, Disc Number, Year, Genre, Composer, Comment и Lyrics. Тексты песен хранятся в отдельной таблице `track_lyrics`.

Обложку можно заменить в двух местах: внутри файла и во внешнем файле `cover.jpg` или `folder.jpg` в папке альбома. Замена внешнего файла идёт через журнал файловых операций и отменяется так же, как правка тегов.

Форматы тегов: ID3v2, Vorbis Comments, атомы MP4, APEv2 и ASF. Основные форматы обслуживает `lofty`, для WMA, DSF, DFF, TTA и MKA подключается TagLib.

Редактор работает на уровне Mp3tag: таблица с правкой в ячейках, преобразования между тегами и именами файлов, действия, нумерация. Он описан в [metadata-editor.md](metadata-editor.md).

Для треков из образа с листом CUE редактор правит сам лист, аудиофайл остаётся нетронутым.

### Файловый менеджер

Любая операция сначала записывается в журнал как запланированная, затем выполняется, затем отмечается выполненной. Массовая операция показывает предварительный список: что было и что станет. Конфликты имён разрешаются выбранным правилом.

Удаление отправляет файлы в корзину Windows. Удаление без корзины требует отдельного подтверждения с числом файлов и общим размером.

Переименование и перемещение отменяются по журналу. После каждой операции медиатека обновляется напрямую, без ожидания наблюдателя.

Переименование по шаблону (`%albumartist%\%album%\%track% - %title%`) использует те же поля, что и язык Query.

Поиск дубликатов работает на трёх уровнях: одинаковые файлы по полному хешу, одинаковый звук при разных тегах по отпечатку аудиоданных, вероятные дубликаты по исполнителю, названию и длительности. Сравнение по акустическому отпечатку отнесено к долгосрочным возможностям.

### Обложки

Источники: встроенное изображение и файлы `cover`, `folder`, `front` в папке альбома. Исходник адресуется хешем содержимого, одинаковые обложки хранятся один раз. Для интерфейса готовятся уменьшенные копии трёх размеров в WebP. Интерфейс получает их по адресу `vyra-art://<hash>/<size>` с вечным кешированием.

### Плейлисты, поиск, навигация

Плейлисты импортируются и экспортируются в форматах M3U, M3U8 и PLS. При экспорте пользователь выбирает относительные или абсолютные пути. При импорте строки сопоставляются с медиатекой по пути, затем по имени файла; несопоставленные строки показываются отдельным списком. Кодировка M3U определяется автоматически, M3U8 всегда читается как UTF-8.

Поиск идёт по всем полям и отвечает на каждое нажатие клавиши. Префиксы находит индекс FTS5. Устойчивость к опечаткам даёт триграммный индекс: результаты ранжируются по доле совпавших триграмм.

Представление «Папки» показывает дерево из таблицы `folders` и играет папку как контекст. Остальные представления (исполнители, альбомы, все треки, недавно добавленные, часто играемые, избранное) собраны из виджетов на языке Query.

### Ошибки и журнал

У каждого крейта свой тип ошибки на `thiserror`. На границе IPC ошибка превращается в стабильный код с параметрами, например `audio.device_busy` и имя устройства. Текст сообщения берётся из каталога строк на фронтенде, поэтому правила для текстов применяются в одном месте.

Журнал ведётся через `tracing` в файлы с ротацией. Уровень задаётся по подсистемам. Команда «Собрать диагностику» упаковывает журналы, сведения о системе и возможности аудиоустройств в архив, который пользователь может приложить к сообщению о проблеме. Сама программа ничего не отправляет.

## 4. Связка Tauri и Rust

Оболочка в `apps/desktop/src-tauri` тонкая. Она превращает вызовы IPC в вызовы `vyra-core` и обратно, логики в ней нет.

| Механизм | Для чего | Примеры |
| --- | --- | --- |
| Команды | запрос и ответ | `playback.play`, `library.query`, `layouts.save`, `metadata.write` |
| События | изменения состояния от ядра | `playback:state`, `queue:changed`, `library:changed`, `audio:signal-path`, `profile:changed` |
| Каналы | потоки данных | ход сканирования, ход файловой операции, кадры спектра для визуализатора |
| Протоколы | двоичные ресурсы | `vyra-art://`, `vyra-plugin://` |

Привязки для TypeScript генерируются из сигнатур Rust. Рассогласование типов между ядром и интерфейсом становится ошибкой компиляции.

Позиция воспроизведения не шлётся на каждый кадр. Ядро четыре раза в секунду и при каждом изменении состояния передаёт опорную точку: позиция, отметка времени, идёт ли воспроизведение. Интерфейс интерполирует между точками на своей частоте кадров.

Ответ команды не превышает одной страницы. Списки запрашиваются окнами по мере прокрутки.

Права окон разведены средствами Tauri. Главное окно получает полный набор команд, мини-плеер только воспроизведение и очередь. Содержимое плагинов не получает ничего и общается через мост.

Событие `library:changed` несёт виды и идентификаторы затронутых сущностей. Фронтенд сбрасывает кеш только у связанных запросов.

### Версии интерфейсов

Внутренний IPC публичным API не является: ядро и фронтенд выпускаются вместе. При запуске они сверяют номер версии, это защищает от устаревшего кеша WebView.

Версионируются поверхности, которые видит кто-то снаружи:

- API плагинов, пакеты WIT и SDK для TypeScript;
- форматы файлов `.vyralayout`, `.vyratheme`, `.vyrabackup`, `.vyraplugin`, у каждого есть поле `schema`;
- схемы баз данных с миграциями.

## 7. Тесты

| Уровень | Что проверяется | Где идёт |
| --- | --- | --- |
| Модульные | язык Query, определение альбомов, очередь, миграции | CI |
| Звук без устройства | bit-perfect, gapless, перемотка на бэкенде `null` | CI |
| Сканер | фикстуры с испорченными тегами, стабильность uid | CI |
| Интерфейс | компоненты, схемы макетов, миграции документов | CI |
| Производительность | время кадра в сценариях прокрутки, скорость сканирования | эталонная машина |
| Устройства | монопольный режим, переключение, отключение на ходу | вручную по списку |

CI работает на Windows. Настоящих аудиоустройств там нет, поэтому всё, что можно проверить без железа, проверяется на бэкенде `null`.
