# Редактор метаданных

Требование от 20 ноября 2026 года: редактор работает на уровне Mp3tag и меняет все поля и форматы тегов из списка требований, включая WMA. Режим остаётся ручным: в файл ничего не пишется без команды пользователя.

Сетевые источники вынесены в плагин: основная программа работает без интернета, а плагин с разрешениями `network` и `library = "suggest"` приносит предложения в тот же предпросмотр.

## Сессия правки

Редактор читает теги прямо из файлов. В базе лежат только поля, нужные медиатеке, а редактор обязан показать всё содержимое тега, включая чужие и нестандартные кадры.

Открыть в редакторе можно выделение из любого представления медиатеки, папку или файлы, которых в медиатеке нет.

Правки копятся в памяти. Изменённые ячейки подсвечены, в заголовке стоит счётчик затронутых файлов. Кнопка «Сохранить» записывает всё разом, «Отменить всё» возвращает исходное состояние. Отмена и повтор работают по шагам внутри сессии.

После записи действует журнал `file_ops`: в нём лежит полный снимок прежнего тега каждого файла, поэтому запись можно откатить и на следующий день.

Mp3tag часть операций пишет в файлы сразу. Здесь всё идёт через «Сохранить»: так требует ручной режим и так безопаснее на тысячах файлов. Это отличие вынесено в Р24.

## Модель полей

У каждого поля одно имя во всех форматах. Таблица соответствий задаёт, где оно хранится:

| Поле | ID3v2.4 | Vorbis | MP4 | APEv2 | ASF (WMA) |
| --- | --- | --- | --- | --- | --- |
| TITLE | `TIT2` | `TITLE` | `©nam` | `Title` | `Title` |
| ARTIST | `TPE1` | `ARTIST` | `©ART` | `Artist` | `Author` |
| ALBUM | `TALB` | `ALBUM` | `©alb` | `Album` | `WM/AlbumTitle` |
| ALBUMARTIST | `TPE2` | `ALBUMARTIST` | `aART` | `Album Artist` | `WM/AlbumArtist` |
| TRACK | `TRCK` | `TRACKNUMBER` | `trkn` | `Track` | `WM/TrackNumber` |
| DISCNUMBER | `TPOS` | `DISCNUMBER` | `disk` | `Disc` | `WM/PartOfSet` |
| YEAR | `TDRC` | `DATE` | `©day` | `Year` | `WM/Year` |
| GENRE | `TCON` | `GENRE` | `©gen` | `Genre` | `WM/Genre` |
| COMPOSER | `TCOM` | `COMPOSER` | `©wrt` | `Composer` | `WM/Composer` |
| COMMENT | `COMM` | `COMMENT` | `©cmt` | `Comment` | `Description` |
| LYRICS | `USLT` | `LYRICS` | `©lyr` | `Lyrics` | `WM/Lyrics` |

Поле, которого нет в таблице, проходит как есть под собственным именем: `TXXX` в ID3, произвольный ключ в Vorbis, атом `----` в MP4. Так пользователь заводит свои поля.

Несколько значений у поля хранятся средствами формата: отдельные строки в Vorbis, разделитель в ID3v2.4. В таблице они показаны через точку с запятой.

## Форматные строки

Одна маленькая языковая конструкция обслуживает преобразования, переименование в файловом менеджере, нумерацию и экспорт.

```
%artist% - %title%
%albumartist%\%album%\$num(%track%,2) - %title%
$if(%discnumber%,%discnumber%-,)$num(%track%,2) %title%
```

- `%поле%` подставляет значение поля.
- `$функция(...)` вызывает функцию.
- `[...]` выводит содержимое, только если поле внутри непустое.

Первый набор функций: `$num`, `$upper`, `$lower`, `$caps`, `$left`, `$right`, `$mid`, `$len`, `$trim`, `$replace`, `$regexp`, `$if`, `$if2`, `$eql`, `$and`, `$or`, `$not`.

Служебные поля: `%_filename%`, `%_ext%`, `%_directory%`, `%_path%`, `%_codec%`, `%_bitrate%`, `%_length%`, `%_counter%`.

Синтаксис совпадает с привычным по Mp3tag и foobar2000. Пользователь переносит свои шаблоны без переписывания.

Реализация одна, в модуле `vyra-metadata::format`. Разбор имени файла по шаблону (имя файла в тег) использует те же заполнители в обратную сторону.

## Действия

Действие описывает одну операцию над полем или файлом. Типы первого набора:

- замена текста, обычная и по регулярному выражению;
- смена регистра;
- значение по форматной строке;
- удаление полей и удаление всех, кроме перечисленных;
- разделение поля по разделителю и слияние повторов;
- добавление обложки из файла, выгрузка обложки в файл, изменение размера обложки;
- угадывание полей из произвольной строки по шаблону.

Группа действий хранится в профиле как документ JSON и запускается одной командой на выделении. Группы можно экспортировать и импортировать файлом.

## Нумерация

Мастер задаёт начальный номер, число ведущих нулей, запись в виде «номер/всего», сброс счётчика в каждой папке и номер диска. Порядок берётся из текущей сортировки таблицы.

## Обложки

Файл может нести несколько изображений с типами: передняя сторона, задняя, буклет. Редактор показывает размер в пикселях и в байтах. При добавлении изображение можно уменьшить до заданной стороны и перекодировать в JPEG.

Внешняя обложка `cover.jpg` или `folder.jpg` меняется здесь же, через журнал файловых операций.

## Предпросмотр и запись

Преобразование, действие и нумерация сначала показывают таблицу «было и стало» для всех затронутых файлов. После подтверждения изменения попадают в сессию правки.

Запись идёт в пуле потоков с индикатором хода и отменой. Файл, который не удалось записать (занят, защищён от записи, повреждён), не останавливает остальные: ошибки собираются в список с причиной по каждому файлу.

Играющий файл записывается после окончания трека. Для треков из образа с листом CUE правится лист.

После записи изменённые файлы сразу перечитываются в медиатеку.

## Движки тегов

```rust
trait TagBackend {
    fn supports(&self, kind: FileKind) -> bool;
    fn read(&self, path: &Path) -> Result<RawTags, TagError>;
    fn write(&self, path: &Path, tags: &RawTags, options: &WriteOptions) -> Result<(), TagError>;
}
```

Движков два.

`lofty` обслуживает MP3, FLAC, OGG, Opus, MP4, APE, WavPack, WAV и AIFF. Он написан на Rust, даёт доступ к отдельным кадрам тега и работает в сканере.

TagLib 2.3 обслуживает WMA, DSF, DFF, TTA и MKA. Это библиотека на C++, она читает и пишет все пять форматов; Matroska в ней появилась в версии 2.2. Подключается через её привязки для C, в которых есть работа с полями и с обложками.

TAK хранит тег APEv2 в конце файла. Для него хватает разбора APEv2 из `lofty`, применённого к файлу напрямую.

Почему не один TagLib на всё. Сканер читает сотни тысяч чужих файлов, среди них попадаются повреждённые. Разбор на Rust при ошибке возвращает ошибку, разбор на C++ может уронить процесс. Поэтому основная масса файлов идёт через `lofty`, а TagLib получает только редкие форматы.

TagLib распространяется под LGPL 2.1 и MPL 1.1 на выбор. Обе лицензии совместимы с GPL-3.0, под которой выпускается VYRA.

Сборка TagLib требует CMake и компилятора C++. Это проверяет прототип П12 из [roadmap.md](roadmap.md).

## Производительность

Теги читаются лениво: сначала для строк на экране, остальные в фоне. Таблица виртуализирована, выделение в 10 тысяч файлов не должно ронять частоту кадров.

Преобразования и действия исполняет Rust, интерфейс получает готовую таблицу изменений страницами.

Время записи определяется диском. Запись через временную копию для альбома в высоком разрешении означает копирование гигабайтов; для массовых правок есть запись на месте.

## Место в интерфейсе

Редактор открывается отдельной страницей с таблицей во всю ширину, панелью полей и обложкой сбоку. Быстрая правка одного трека остаётся в обычном диалоге свойств и использует ту же сессию.
