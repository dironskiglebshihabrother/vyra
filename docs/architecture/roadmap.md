Прототипы П2 и П3 закрыты автоматическими тестами. П1 закрыт частично: обе проверки шли на файлах с цифровой тишиной, час непрерывной работы и USB-ЦАП в монопольном режиме ещё впереди.

Что выяснилось по дороге:

- Symphonia не открывает FLAC, у которого в заголовке минимальный размер блока меньше максимального. Так пишет кодировщик `flacenc`; эталонный кодировщик пишет одинаковые значения. Файлы от `flacenc` в коллекциях возможны, для них понадобится обход.
- Кадр FLAC неразумного размера Symphonia пропускает молча. Движок замечает такой пропуск по разрыву во временных отметках пакетов и считает потерянные кадры.

## Как идёт работа

Сроки в неделях ниже показывают относительный объём этапов. Календарную оценку стоит пересчитать после первых двух прототипов, когда будет видна настоящая скорость.

Всё, что можно проверить автоматически, проверяется тестами. Часть проверок требует человека и железа:

- приёмка внешнего вида;
- проверка на слух: щелчки, пропуски, стыки треков;
- проверка на настоящих аудиоустройствах по списку из этого документа;
- установка на чистую машину и поведение SmartScreen.

Для сборки нужны Rust, компилятор C++, Node и WebView2. CMake понадобится к прототипу П12.

## Этап 0. Прототипы

Прототипы отвечают на вопросы, от которых зависит конструкция. Каждый живёт в `tools/` или отдельной ветке и выбрасывается после ответа. Срок этапа: 4–6 недель.

| № | Что проверяется | Когда считается пройденным |
| --- | --- | --- |
| П1 | Вывод WASAPI: общий и монопольный режимы, работа по событию, смена устройства, смена частоты | час воспроизведения без пропусков на встроенном кодеке и на USB-ЦАП; переключение устройства быстрее 300 мс |
| П2 | Декодирование и gapless на Symphonia, отдельно AAC в M4A | склейка двух половин трека совпадает с целым до семпла для MP3, FLAC, ALAC, Vorbis; для AAC найден рабочий способ или зафиксировано ограничение |
| П3 | Bit-perfect | хеш вывода на бэкенде `null` равен эталону; запись через цифровую петлю S/PDIF или USB совпадает с исходным файлом побитно |
| П4 | Скорость интерфейса | сетка из 50 тысяч альбомов и список из 250 тысяч треков прокручиваются с кадром не длиннее 16,7 мс на эталонной машине; то же с материалом «стекло» на панели плеера |
| П5 | Пропускная способность IPC | постраничная выдача, опорные точки позиции и 60 кадров спектра в секунду идут одновременно без роста задержек |
| П6 | Сканер | 100 тысяч файлов с SSD, HDD и сетевой папки; во время сканирования звук идёт без пропусков; измерены скорость чтения тегов и записи в базу |
| П7 | FFmpeg за границей DLL | `vyra_ffmpeg.dll` загружается при наличии и декодирует WMA, APE, DTS; программа запускается и без неё |
| П8 | Окно без рамки | свои кнопки, изменение размера, прилипание, меню раскладок Snap в Windows 11, масштабы 100%, 150%, 200%, два монитора с разным масштабом |
| П9 | Установщик | окно на WebView2 поверх тихого пакета NSIS; запасное окно на машине без WebView2; установка без прав администратора; регистрация типов файлов с иконками |
| П10 | Плагины | iframe с чужим origin не видит API Tauri; измерены прибавка размера от Wasmtime и скорость эквалайзера в WASM против нативного |
| П11 | Открытие из проводника | один экземпляр, сбор нескольких файлов в один запрос, карточка SMTC при закрытом окне |

| П12 | TagLib как второй движок тегов | статическая сборка под MSVC из `cargo build`; запись и чтение всех полей и обложки для WMA, DSF, DFF, TTA и MKA; набор повреждённых файлов не роняет процесс |

П10 нужен перед этапом плагинов, П12 перед версией 0.3, остальные перед MVP.

### Список ручной проверки устройств

Используется в П1 и перед каждым выпуском:

1. Встроенный кодек, общий режим, смена системной частоты во время воспроизведения.
2. USB-ЦАП, монопольный режим, треки 44,1, 48, 96 и 192 кГц подряд.
3. Отключение USB-ЦАП во время воспроизведения и возврат.
4. Bluetooth-наушники: подключение и отключение на ходу.
5. Монопольный режим, когда устройство занято браузером.
6. Сон и пробуждение компьютера на паузе и во время воспроизведения.
7. HDMI-выход на монитор или ресивер.

## MVP, версия 0.1

Цель: плеер, которым можно пользоваться каждый день на собственной коллекции. Срок: 3–4 месяца после прототипов.

**Звук.** MP3, FLAC, WAV, AIFF, ALAC, AAC-LC, OGG Vorbis. WASAPI в общем и монопольном режимах. Gapless. Переключение устройств без перезапуска. ReplayGain из тегов. Строка пути сигнала с признаком bit-perfect.

**Медиатека.** Несколько корневых папок, сканирование, наблюдение за изменениями. Исполнители, альбомы, треки, жанры. Определение альбомов с оценкой уверенности. Кеш обложек. Полнотекстовый поиск.

**Воспроизведение.** Все правила контекста, очередь, shuffle и повтор, команда «Только этот трек». Восстановление после сбоя.

**Личные данные.** Избранное, рейтинги, сбор статистики, ручные плейлисты. Профиль один, но данные уже разложены по схеме с несколькими профилями.

**Интерфейс.** Тёмная тема. Окно без рамки со своими кнопками. Страницы рисуются движком из документов макетов, редактора ещё нет. Экран «Сейчас играет», очередь, поиск, настройки. Выбор акцентного цвета.

**Система.** Один экземпляр, открытие файлов и папок, SMTC и мультимедийные клавиши, трей. Для внутренних сборок используется стандартный установщик Tauri.

**Основа.** Миграции, журнал, копия базы перед миграцией, тестовые фикстуры, CI.

В MVP не входят: редактор макетов, темы, редактор тегов, файловый менеджер, умные плейлисты, эквалайзер, FFmpeg, интерфейс профилей, плагины.

## Версии до 1.0

Порядок отражает приоритеты брифа: кастомизация названа главным преимуществом, поэтому идёт сразу после MVP.

| Версия | Содержание | Срок |
| --- | --- | --- |
| 0.2 Кастомизация | редактор макетов с отменой действий, набор виджетов, редактор sidebar, рабочие пространства, редактор тем, светлая тема, импорт и экспорт макетов и тем, мини-плеер, глобальные горячие клавиши | 8–10 недель |
| 0.3 Коллекция | редактор метаданных, этап А: таблица, массовая правка, преобразования, нумерация, обложки; список проблем с предложениями, файловый менеджер с журналом и отменой, пропавшие файлы, дубликаты первых двух уровней, умные плейлисты, расширенный поиск, листы CUE, импорт и экспорт плейлистов M3U и PLS, представление «Папки», правила пропуска при сканировании | 13–15 недель |
| 0.4 Звук | параметрический эквалайзер, цепочка DSP, настройки ресемплера, анализ громкости R128, режим «Только bit-perfect», Opus, пакет FFmpeg с WMA, APE, WavPack, TAK, TTA, MKA, AC3 и DTS | 6–8 недель |

Срок вырос после списка требований от 20 ноября 2026 года. В версию 0.3 перенесены листы CUE и добавлен обмен плейлистами, это две недели, решение Р22. Редактор метаданных уровня Mp3tag добавил по три недели к версиям 0.3 и 0.5, решение Р24.

## После 1.0

- Хост плагинов: сначала UI-плагины, затем core, затем DSP. SDK и документация для авторов.
- Собственные плагины как проверка API: тексты песен, Last.fm, Discord RPC, визуализатор.
- Локальная синхронизация в выбранном по Р7 варианте.
- DSD: разбор DSF и DFF, вывод DoP, преобразование в PCM.
- ASIO. Лицензия GPL-3.0 позволяет использовать SDK без соглашения со Steinberg.
- Собственное окно трея, список переходов в панели задач.

## Долгосрочные возможности

- Хостинг нативных плагинов CLAP и VST3 в отдельном процессе.
- Дубликаты по акустическому отпечатку.
- Каталог плагинов с проверкой издателей.
- Передача AC3 и DTS на ресивер без декодирования.
- Управление с телефона в домашней сети.
- Группировка изданий по MusicBrainz через плагин.

## Риски

| Риск | Вероятность | Что делаем |
| --- | --- | --- |
| Интерфейс на WebView2 не держит 60 кадров на слабой графике при размытии | средняя | П4 до начала вёрстки; размытие только на малых поверхностях; тема по умолчанию без стекла |
| Меню раскладок Snap не работает с кнопкой из HTML | средняя | П8; запасной вариант: меню по наведению недоступно, раскладки вызываются сочетанием Win + Z |
| Gapless для AAC требует собственного разбора контейнера | высокая | П2; в худшем случае AAC играет через FFmpeg |
| API `rubato` и `tauri-specta` меняется между выпусками | высокая | точные версии в `Cargo.toml`, обёртки своими трейтами |
| Монопольный режим ведёт себя по-разному у разных драйверов | высокая | кеш возможностей устройства, список ручной проверки, подробная диагностика |
| Объём требований велик для малой команды | высокая | жёсткие границы MVP, плагины после 1.0 |
